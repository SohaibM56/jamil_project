# Jamil Project - Flutter App Architecture

This project follows an **MVVM architecture** using **GetX** for state management, navigation, and dependency injection.

## 🚀 Getting Started

1.  **Install Dependencies:**
    ```bash
    flutter pub get
    ```

2.  **Run the App:**
    ```bash
    flutter run
    ```

## 📂 Folder Structure

- `lib/main.dart`: App entry point (system UI setup, `Firebase.initializeApp()`).
- `lib/firebase_options.dart`: Generated by the FlutterFire CLI; per-platform `FirebaseOptions`.
- `lib/src/app.dart`: Root widget (`GetMaterialApp`, theme, `ScreenUtilInit`).
- `lib/src/mvvm/`: Core source code, split by MVVM layer.
  - `viewModels/`: `GetxController` classes, one per screen (auth, dashboard, login, signup, forgot, splash).
  - `views/`: `GetView<Controller>` widgets, one per screen.
- `lib/src/repos/`: Repositories (`AuthRepository`, `CardRepository`, `StorageRepository`) that sit between controllers and data sources.
- `lib/src/models/`: Plain data models (`CardModel`, `CardLink`) mirroring the Firestore schema.
- `lib/src/config/`: Routing (`app_router.dart`), DI bindings (`app_bindings.dart`), theme/colors, asset paths, and layout extensions.
- `lib/src/widgets/`: Shared widgets (dialogs, text fields, bottom nav, icons).

## ⚙️ Key Technologies

- **State Management / DI / Navigation:** GetX (`GetxController`, `Get.put`/`Get.find`, `GetPage`)
- **Backend:** Firebase Auth (email/password) + Cloud Firestore + Firebase Storage (`firebase_core`, `firebase_auth`, `cloud_firestore`, `firebase_storage`)
- **Image picking:** image_picker (avatar upload, camera or gallery)
- **Responsive Layout:** flutter_screenutil
- **Fonts:** Custom fonts Satoshi and ClashDisplay, with Google Fonts (Poppins) as the default text theme
- **QR Codes:** pretty_qr_code
- **SVG Icons:** flutter_svg
- **Image Cropping:** image_cropper (customizable square crop for avatars)

## ⚙️ Project Configuration

- **Security Rules:** `firestore.rules` and `storage.rules` are maintained in the root directory for version control and single-source-of-truth.
- **Firebase CLI:** Use `firebase deploy --only firestore:rules,storage:rules` to sync local rules with the server.

## 🧠 Architecture Highlights

- **Scalable Navigation:** Routes are defined in `app_router.dart` as `GetPage`s; each page owns its own `Binding` for lazy controller creation.
- **Route Guarding:** `AuthMiddleware` redirects between the auth screens and the dashboard based on `AuthController.isAuthenticated`.
- **Persistent Auth:** Firebase Auth persists the signed-in session across restarts; `SplashController` checks `FirebaseAuth.instance.currentUser` (via `AuthController.isAuthenticated`) to route to Dashboard or Login.
- **Loading/Error Handling:** Auth actions use `.obs` loading/error state on `AuthController`, surfaced via `Obx` and `Get.snackbar`.
- **Separation of Concerns:** Views only interact with their controller; controllers talk to repositories, not data sources directly.
